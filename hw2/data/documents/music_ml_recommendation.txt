Machine Learning in Music Recommendation and Classification

SPOTIFY'S RECOMMENDATION SYSTEM ARCHITECTURE

Spotify's recommendation engine is one of the most sophisticated in the streaming industry, combining three core approaches:

1. COLLABORATIVE FILTERING
Collaborative filtering identifies users with similar listening histories and recommends tracks they enjoyed. If User A and User B have 70% overlap in their music tastes, tracks that User B loves but User A hasn't heard are strong candidates for recommendation. Spotify uses matrix factorization techniques to compute these user-item embeddings at scale across its 600+ million users.

2. CONTENT-BASED FILTERING
Content-based filtering uses audio features (danceability, energy, tempo, etc.) to find tracks similar to ones the user already enjoys. If a user listens repeatedly to high-energy, high-danceability tracks, the system recommends tracks with similar feature profiles. Natural language processing applied to blog posts, reviews, and social media also generates "cultural" embeddings that complement audio feature embeddings.

3. DEEP LEARNING ON RAW AUDIO
For cold-start problems (new tracks with no listening history), Spotify uses convolutional neural networks trained on raw audio spectrograms to generate latent representations. These deep embeddings capture timbral and rhythmic information that structured audio features may miss.

MUSIC POPULARITY PREDICTION

Predicting whether a track will become popular before its release is an active area of research. Common approaches include:

Random Forest and Gradient Boosting: Tree-based models trained on pre-release audio features achieve reasonable accuracy (ROC-AUC of 0.70–0.80) in predicting whether a track will reach popularity > 50 within three months. The most important features are consistently energy, danceability, and loudness.

Neural Networks: Feed-forward neural networks with 2–4 hidden layers trained on audio features show similar performance to tree-based models on tabular data. Convolutional networks on spectrograms can outperform both when raw audio is available.

Genre as a Feature: Including genre significantly improves popularity prediction, but introduces data leakage risk if genre is not available at inference time for new tracks.

CLASSIFICATION APPROACHES

Binary Classification (Popular vs. Not Popular):
The most common framing is to binarize the popularity score at a threshold (typically 50 or 60) and frame the problem as binary classification. Class imbalance is common — at a threshold of 60, roughly 15–25% of tracks qualify as "popular." Techniques like SMOTE, class weighting, or adjusted decision thresholds are used to address this.

Multi-class Genre Classification:
Predicting genre from audio features is a more challenging multi-class problem with 125 possible classes in the Spotify dataset. Hierarchical classification (first predict broad genre family, then sub-genre) improves performance over flat multi-class classifiers.

EVALUATION METRICS FOR MUSIC ML TASKS

For binary popularity classification:
- ROC-AUC: Most informative metric for imbalanced datasets
- F1-score (macro): Balances precision and recall across classes
- Precision@K: Important for recommendation contexts

For multi-class genre classification:
- Top-1 Accuracy: Standard metric
- Top-3 Accuracy: More appropriate given genre ambiguity (many tracks span multiple genres)
- Weighted F1-score: Accounts for class imbalance across genres

FEATURE ENGINEERING FOR MUSIC ML
Effective derived features used in research:
- energy_danceability_ratio: captures the balance between raw intensity and rhythmic appeal
- loudness_normalized: loudness mapped to [0,1] since raw dB is negative
- acoustic_minus_electric: (acousticness) - (1 - instrumentalness), captures acoustic purity
- tempo_normalized: tempo divided by typical max (250 BPM) for scale consistency
